# 第二轮同步提速验证

本次在 AKShare 数据源上启用三路查询及增量批次发布，全局请求起始间隔仍为 150 毫秒。查询日期固定为 2026-09-11。Wind 取数能力保留，原有 287 条 Wind 请求证据和 25 个会话未增加或改变。

## 已验证的改动

- **复用未变个券的计算结果**：比较目录、状态、详情、来源证据、同日原始行情及冲突，只重新计算发生变化的券。跨任务、跨数据库、进程重启、外部发布新版本或基准/规则变化会使缓存失效。汇总依旧从全部样本精确重算。
- **避免每批重写整天 JSON**：只序列化变化记录，个券索引、摘要和存储元数据在同一事务提交。旧 JSON 继续可读，完整 API 和 CSV 导出在单个读事务内重建全部个券，保持原格式。
- **三路有界并发**：同样 150 毫秒全局节流，保留暂停恢复、三次暂时失败重试、限流停止、代次校验及进程退出清理。

## 对照结果

真实任务各取完整 180 秒窗口：优化前 **725 只 / 3 分钟（241.7 只/分钟）**，优化后 **1,054 只 / 3 分钟（351.3 只/分钟）**，持续吞吐提升约 **45.4%**。优化后最近一分钟完成 353 只，窗口内记录的 1,051 次详情 HTTP 响应均为 200。请求记录按发起时间、完成数按条目提交时间统计，窗口边界使两者相差 3 条。

对照窗口分别为 2026-09-13 00:23:33–00:26:33、00:32:08–00:35:08（Asia/Shanghai）。两次均为同一真实同步任务，但查询的债券和上游响应时间不同；前窗还包含部分离线验证期间的本机负载，实际提速比例不能视为严格控制网络与 CPU 条件的承诺。00:35:08 检查时任务保持 running / generation 6，完成 12,706 只，待处理 5,830 只，另有 1 条失败和 3 条无交易代码的登记项。

18,540 只券、每批 250 份新增详情的固定离线数据：第二批发布 **4.103 秒 → 0.380 秒**，耗时减少约 91%。三个阶段的完整业务结果相同，最终逐券差异为零。详见 [发布基准](publication.md)。

24 只券、固定 400 毫秒网络等待：两路 **5.365 秒 → 三路 4.190 秒**，吞吐提高约 28%。固定 120 毫秒等待时，两路与三路约为 3.88 / 3.93 秒，受全局节流约束，没有明显收益。没有为本次离线基准请求外网。

真实库首次切换和冷重建耗时 5.80 秒，逐券、汇总及基准内容与切换前一致；后续无变化批次耗时 **0.52 秒**，不重新计算任何个券。该读写对照期间任务暂停，之后已恢复至 generation 6。

## 回归与页面

249 项后端测试全部通过，包含 8 项增量业务回归和 5 项索引存储回归。真实双 SQLite/WAL 连接验证：读取过程中另一连接提交新版，读者仍取得完整旧快照，下一次读取才取得新版。写入中断、旧版本和过期任务代次均不会产生半份结果或污染计算缓存。

后台三路同步运行期间，浏览器首屏 **364 毫秒**、翻页 **153 毫秒**，没有长任务；6 项真实页面检查通过。完整导出得到全部 **209 条**可汇总样本，分页、单券来源证据、样本汇总和 37 地区矩阵均正常。
