# 多工具取数与数据溯源（2026-09-12）

本次按用户新增要求，将已取得的全部来源数据保留下来，不再只保存最终汇总。本文更新原设计中个券仅参与当次计算的存储边界。

## 执行流程

1. 创建持久化任务与独立取数会话，记录目标日期、地区、规则、批量大小及字段映射版本。
2. 连接官方债券 MCP 并保存实际工具目录。
3. 按地区独立请求主证券代码去重总数和名单。返回被截断时按发行日期递归分批，核对日期范围、主体、分批重叠及总数；不能确认完整性时停止发布。
4. 按批次分别调用档案、发行主体、行情工具，获取发行档案、原始发行规模、债券分类、提前偿还、赎回、中债估值、实际估值日期、历史剩余期限及久期。批量响应漏券时逐券补取一次。财务工具虽然被发现，但当前加权估值不需要它的财务字段，因此不额外调用。
5. 仅依据来源明确返回的身份关系合并跨市场代码。保留原始字段、单位和单元格位置；未知值保持未知。计算必需字段不完整、整批估值缺失或口径冲突时停止发布。
6. 用固定 Decimal 规则计算，记录逐券纳入、剔除、重复与冲突原因。全国完整取数通过后原子发布 1,554 个分组位置；失败不会覆盖以前的成功快照。大模型不负责补造字段或计算数值。

## 保存内容

主库为 `runtime/wind-wind.sqlite3`，显式演示模式使用独立演示库。新真实请求在发送前写入数据库，收到响应行后逐段提交，因此页面关闭、失败与重试不删除已取得的证据。

| 数据表 | 内容 |
|---|---|
| source_sessions | 取数会话、任务关联、目标日期、配置与规则版本 |
| source_requests | JSON-RPC 请求、工具、时间、HTTP 状态、完整响应、错误与 SHA-256 |
| source_response_parts | 已收到的 SSE/JSON 响应行，含失败前的片段 |
| source_artifacts | 工具目录、名单分批/覆盖证据、合并批次、计算结果、失败报告；新任务的映射与计算代码副本 |
| bond_observations | 每次运行的规范化个券、字段来源、筛选决定、分组、重复身份 |
| aggregate_results | 每次成功任务的汇总结果，旧版本保留 |
| summary_versions | 摘要每次生成的版本，包括失败版本 |
| source_imports | 旧版诊断文件导入的文件名与内容哈希，防止重复导入 |

不设置自动删除。重新运行创建新任务和新会话；最新快照、最新核验报告和最新摘要只是索引，原始历史继续保留。Wind Key 仍在单独配置库中使用 DPAPI 加密保存；认证头不进入来源记录，响应中出现同一 Key 字符串时会脱敏。响应哈希用于一致性核对，不代表防篡改存储或外部备份。

旧版已有的诊断 JSON 已作为带文件哈希的证据导入，保留原文件；旧版没有记录的请求时间、已被覆盖的旧内容和过去未保存的个券不能追补。新实现从启用后持续留档。

## 页面与导出

侧栏「数据溯源」打开 `/trace`。更新记录的「溯源」按钮按任务定位，已发布单元格的「追溯此分组个券」按地区、发行组、期限和债券口径定位。未能确定分组的缺失记录在任务全部个券中查看。

逐券字段详情可点击原始单元格来源，跳转对应请求和响应。表、行、列编号从 0 开始。JSON 导出包含该会话全部请求、响应片段、证据附件、关联任务的全部个券与计算结果和摘要版本，不受页面分页限制。

两轮的全部原始响应已保存，原始表中的记录数量超过用于字段可用性核验的 10 条规范化个券。失败记录保留当时的原因；后续映射改进不会改写旧任务的判断。

目前不能判定缺失究竟由账号权限、字段覆盖还是自然语言接口能力导致。连接成功不意味着必需字段齐备，不能据此推断全市场当日无估值。需要 Wind 来源返回可验证的字段与完整名单，才能真实发布全国矩阵。

完整成功路径通过模拟 Wind JSON-RPC 提供方验证，包括多工具合并、2 券发行规模加权结果 1.75000000、1,554 个分组的发布，以及字段定位原始响应。另验证截断、失败保留、重试保留前版、HTTP 错误体、凭据脱敏、摘要历史与进程中断片段保留。浏览器验证覆盖任务筛选、字段追溯、完整导出、刷新和窄屏显示。测试数据与真实来源证据明确分开。
