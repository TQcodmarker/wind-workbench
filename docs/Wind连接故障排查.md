# Wind MCP 连接失败排查（2026-09-12）

## 现象与证据

- 本机 `/api/source` 显示已配置 Key；调用 `/api/source/test` 约 0.01 秒返回通用连接失败，未输出或提取用户 Key。
- 在启动旧后端的受限环境中，DNS 正常，但向固定 Wind MCP 地址建连报 `httpx.ConnectError: [WinError 10013]`，约 0.04 秒失败。
- 同一不带 Key 的初始化请求在正常本机权限下约 0.4 秒收到 Wind 的 HTTP 401，说明远端可达；401 是无鉴权请求的预期结果，不说明用户 Key 无效。

因此，已确认的首要阻断点是旧后端运行环境的出网限制。旧代码把网络异常、响应解析异常等全部转换成“连接失败，请检查网络与服务权限”，掩盖了阶段差异。

## 已修复

- 结束监听 127.0.0.1:8765 的旧受限进程，在正常本机权限下重新启动后端。
- `backend/wind_connection.py` 分别识别本机网络权限限制、网络连接失败、TLS 校验、超时、HTTP 401/403、MCP 协议错误与响应解析失败；不回显 Key 或上游原始错误内容。
- 初始化返回 SSE 时，收到对应结果立即返回，不等待长连接关闭。
- 前端测试失败使用错误提示，不再显示成绿色成功消息。

## 验证与剩余步骤

- 后端 22 项测试通过，包括 4 项连接回归测试；前端构建通过，重启后页面正常加载。
- 在正常本机环境以明确无效的诊断占位符调用修复后的同一探测函数，返回 Wind HTTP 401，验证请求已到达远端并正确分类。
- 用户真实 Key 仅存在旧进程内存中，重启已清除；没有提取、记录或迁移它。需要用户在页面重新保存 Key 后再次验证，才能确定该 Key 的有效性与债券服务权限。
