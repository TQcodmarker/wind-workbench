**与本机清单匹配后的实际覆盖**

对 14,023 个本机清单代码，仅按公开银行间 `bondcode + .IB` 与 `excelCode` 精确匹配，不猜测跨市场身份：

- 匹配到 **358 个清单代码**，都至少有一条非空最新成交收益率。
- 其中 **160 个**此前已有 Wind 返回，**198 个**此前未取得资料。
- 匹配记录行情日期为 **2026-09-11**；不能把 2026-09-12 请求时间当作新行情时间。
- 原始列表有重复代码。记录数、不同代码数和经济意义上的债券数量须分别统计；相同记录可去重，非空冲突应保留证据再处理。

例：21云南09（173695.IB）、23四川69（198777.IB）、23湖南债135（2371326.IB）在此次公开列表有成交行情。这些是成交收益率，不能改名为中债估值收益率，也不能直接填入现有 Wind 收盘价 YTM 的同一快照。

**第一版建议做四项功能**

| 功能 | 实现方式 | 数据缺失时 |
|---|---|---|
| 国债曲线与走势 | 取公开曲线，按曲线名称、日期、期限存储，计算同口径 BP 变化 | 保留最近成功日期，明确显示更新失败或暂无发布 |
| 地方债／国债个券行情 | 保存公开成交列表，按代码与 ISIN 校验身份，展示价格、收益率、行情时间 | 显示“该公开源暂无记录”，不填 0、不用旧值冒充今日值 |

| 历史数据和文件导入 | 保留已有 4,352 券历史资料及 3,539 个收盘价 YTM；允许导入用户有权使用的免费 CSV／Excel | 已有历史保持原日期，导入数据保留来源和口径 |

后续SDK实测已确认 `bond_local_government_issue_cninfo`、`bond_treasure_issue_cninfo` 可返回发行资料，`bond_info_cm` 补上地方政府债类型后可返回样本基础信息；仍须处理日期、增发及跨市场身份，见[实测报告](/D:/code/wind工作台/docs/AKShare债券接口实测-20260912.md)。

**在现有工作台里的技术实现**

建议使用当前 FastAPI + SQLite + React 技术栈，新增免费数据适配器，无需新增付费服务器或大模型调用。可直接读取已核验的公开响应，不必先引入整个 AKShare 库；AKShare 源码作为字段语义和接口行为参考，原始 JSON 可保留其封装没有展示的代码、ISIN 和时间。

数据路径：公开数据 → 后端采集与字段校验 → SQLite 历史及最新缓存 → 页面查询。

1. 新增 `bond_curves` 与 `public_bond_observations` 等独立存储，保留来源、指标类型、证券身份、来源时间、抓取时间、单位、原始字段和失败状态。不要复用当前 Wind 的 `yieldPct` 作为多种收益率的混合字段。
2. 估值／曲线按发布日期保存；初版以每日更新为主。公开成交列表可先手动更新，后续如确需盘中观察，再按来源允许频率适度轮询。页面每 5–15 秒刷新缓存不意味着来源行情达到同样时效。
3. 单一后端采集任务供全部页面复用，设置请求超时、失败退避及有限重试，避免全量列表被每个浏览器页面重复获取。遇到拒绝访问或验证要求就停止该源自动采集，提供官方页面和文件导入入口。
4. 增加服务端零费用开关：免费模式拒绝新建 Wind 取数、付费源验证及补取任务；任务执行端也检查该开关。已有排队付费任务不得因启动应用自动恢复。免费源失败不能自动回退到 Wind。
5. 当前 v3 仍保留为 Wind 收盘价 YTM 的历史计算规则；公开成交、曲线和中债样本各用自己的来源标签与规则。新增国债视图时，国债不强行归入地方债的 37 地区矩阵。

上述为待实施设计，本轮没有修改应用业务代码、关闭现有服务或启用采集定时任务。

**如果坚持要求每只债券都有估值**

零付费下，目前没有验证到能完整补齐本机清单的中债估值接口。只有发行资料、票息和剩余期限，不能唯一确定当前市场收益率。

在取得可靠价格后，可以补齐应计利息、结算日、计息规则与完整现金流，计算派生 YTM，但应标为“按公开价格计算”，不能称为中债估值。没有单券价格时，第一版只展示同期限国债曲线参考，不把参考曲线收益率填成个券收益率。自建估算模型可另做情景分析，但不能据此宣称完成官方估值补齐。
