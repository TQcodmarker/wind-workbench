# 地方债工作台

本机运行的地方债数据工作台，支持在 AKShare 与 Wind 之间切换。前端使用 React / TypeScript / Vite，后端使用 FastAPI，SQLite 保存数据源选择、历史数据和任务，Python Decimal 执行业务计算。原有 Wind 接入与显式演示模式继续保留。

## 当前默认数据源：AKShare

首次使用真实数据库时默认选择 **AKShare**。在「数据源」页切换到 Wind 或 AKShare 后，选择会保存，重启后继续使用。切换和读取已保存数据不会触发采集；需要手动创建更新任务。每项任务在提交时固定数据源，随后切换页面数据源不会更改已排队任务的来源。同日另一个数据源存在排队或运行任务时，新任务返回冲突提示。

日常「更新 AKShare 数据」按公开成交补充样本，每批最多新增查询 **20 只地方债详情**，设有 240 秒查询时限；全市场目录与静态资料使用下方独立的「全量同步地方债」入口。提供方返回的代码、名称、发行信息和市场收益率会保留来源与口径；缺失字段保持为空。公开市场成交、收益率曲线及指数指标只按自身定义展示，不能称为逐券中债估值收益率或逐券中债修正久期。替代指标会明确标记，原表需要的全量地方债余额、指定曲线及逐券估值仍可能缺失。

AKShare 规则版本为 `rules-akshare-v2-estimated-duration`：只有来源日期等于目标日的**个券公开成交到期收益率**可以按发行规模加权，并按**自行计算的个券修正久期**就近归入 3、5、7、10、15、20、30 年档（等距取较大档）。现金流安排未完整核验时明确标注到期一次还本、计息与复利假设；已知提前偿还或复杂条款而缺少安排的债券保留行情但暂不汇总。剩余期限按 Actual/365 单独展示，不作为久期。指数平均收益率、指数久期及曲线继续仅作参考。即时成交接口不能回查任意历史日期；没有取得目标日数据时保留原缓存，不用最新行情回填历史。旧规则数据重算前归档，详见 [个券久期分组](docs/个券久期分组.md)。

2026-09-13 已将本机 2026-09-11 数据升级到久期分组：18,540 条目录、18,536 只静态详情、469 只有当日成交收益率；可汇总从 209 增至 **461 只**，均明确标为估算久期。其余 8 只有原始清单中的提前偿还提示，待补可靠还本计划。旧 209 只口径已归档，AKShare 与 Wind 原始证据的数量及 SHA-256 均未变化。数据核对见 [升级验证结果](research/akshare-duration-20260913/verified-result.json)。

真实服务首次没有 AKShare 缓存时，会读取工作区内此前验证的 5 只地方债公开数据证据，保留原观测日期和替代指标说明；这些记录不代表全国覆盖。后续实时更新通过 `bond_spot_deal`、`bond_info_cm`、`bond_info_detail_cm`、`bond_index_general_cbond` 和 `bond_china_close_return` 采集，并保存实际请求及响应证据。

AKShare 的样本缓存、规则和任务显示与 Wind 数据分开；AKShare 没有数据时不会自动改用 Wind。部分样本不发布为 Wind 的全国完整矩阵。已有 Wind 快照、个券证据、失败记录和配置均保留，切回 Wind 后继续查看和使用。

2026-09-12 已通过工作台真实更新 2026-09-11 数据：44 次 SDK 查询全部成功，新增 20 只详情后保存 25 只地方债样本，其中 20 只可参与同日成交收益率汇总。原 Wind 的 287 条请求证据与 25 个来源会话数量保持不变。检查结果见 `test-results/akshare-source-migration.json`；这仍是分批样本，不是全量覆盖。162 项后端测试、7 项数据源浏览器检查及原有 16 项演示回归检查通过。

## 全市场地方政府债同步

1. 选择目标日期，在 AKShare 页面点击 **「全量同步地方债」**。接口先保存任务并返回，由独立后台进程继续获取中国货币网公开地方政府债目录和逐券静态资料。
2. 查看同步进度，包括当前阶段、目录分区进度、已完成、失败和待处理数量。目录尚未完整返回时，总数显示未知；不会把首批返回的数量当作全市场总数。
3. 需要停止时点击暂停，当前网络请求结束后停止；之后使用 **继续同步／重试** 从原任务接着处理。已完成的资料保留；重启服务或电脑后，可回到同一任务继续。

同步会优先补齐已有目标日成交行情的债券详情，并在每批保存后重新安排优先顺序。每次保存都会按代码和实际观测日期匹配已经下载的 `bond_spot_deal` 响应，再计算汇总资格；不必反复点击普通更新才能让新档案关联旧行情。只有目录身份的债券也可展示已验证的当日收益率，但必需静态字段未齐时仍不会纳入汇总。

页面分别显示 **目录记录、静态详情、当日个券收益率、可汇总** 四类数量。同步面板另显示有行情的券中有多少已补齐详情。公开行情保留原始查询编号、采集时间和实际观测时间；相同代码同一观测时点有矛盾值时暂不采用，更晚的可靠观测可解除冲突。其他日期、其他数据源以及指数参考不会被当作目标日个券成交行情。

2026-09-12 23:47 实测：2026-09-11 的目录仍为 18,540 只；复用原有两次成交响应后，已展示个券收益率从 41 只增至 469 只。优先补齐这 469 只的详情后，可汇总从 40 只增至 209 只，汇总口径保持不变。Wind 请求与来源会话仍分别为 287 / 25。217 项后端测试、前端构建及真实浏览器验证通过，结果保存在 `research/akshare-sync-optimization-20260912/verified-result.json`。

同步任务固定为 AKShare 和创建时的目标日期，与原有日常更新任务独立。关闭浏览器不会取消已提交的后台任务；执行期间电脑需要保持开机、联网，后台进程需要持续运行。暂停、断网或进程中断后，已有进度保存在本机，恢复后继续处理未完成项目。

**目录和静态资料完整，不等于每日个券行情完整。** 目录按官方发行年份枚举逐项查询，并检查上游分页返回是否齐全；未知或缺失分区不能被标记为全量完成。即使静态同步完成，非活跃券仍可能没有目标日成交收益率，逐券中债估值、修正久期和未偿余额也可能缺失。`catalogComplete` 表示目录是否完整，`marketDataComplete` 保持 `false`，不据此发布全国完整估值矩阵，也不覆盖 Wind 数据。

## Wind 收益率口径（保留）

Wind 新任务按**收盘价到期收益率（%）**取数和计算，规则版本为 `rules-v3-mcp-values-no-clauses`。Wind MCP 返回的非空数值直接采用，有效零值保留；按查询日期归档，保存原始字段名和单位，不额外要求日期、指标类型和价格口径证明列。暂不采集、记录提前偿还和发行人赎回信息，也不将其用于筛选。

已有中债快照、旧 YTM 快照和取数证据保留原口径与当时的筛选规则。页面、规则说明、CSV 和助手按各自快照展示；不同规则版本的快照不直接计算涨跌。升级前排队的旧规则任务会失败并提示重新创建，避免使用新规则执行旧任务。

本次规则调整使用已保存的单券返回及离线样例验证，不新增 Wind 查询，也不据此将单券样本认定为全国覆盖。详见 [到期收益率口径](docs/到期收益率口径.md)。

## Wind 已有数据直接展示

工作台支持「已有个券」「样本汇总」「全国完整结果」。日期没有完整快照时，默认展示本机已经保存的个券数据；整批任务失败不再遮蔽此前成功返回的表格。读取、刷新、筛选和导出这些记录不会调用 Wind。

「全国完整结果」页签在缺少完整快照时，也会按地区和期限展示当日已有的样本汇总，并标记为「已有数据」；未覆盖位置显示“—”，有效零值保留。详情与 CSV 使用已有样本的口径，不生成发布版本。完整快照存在时仍优先展示该快照。估值工作台不显示 Excel 清单进度，也不轮询清单任务。

已有数据按来源会话的查询日期隔离，使用当前字段映射重新整理，保留原始字段名、值、单位和请求来源。资料不全的债券仍显示可用字段；仅符合当前计算规则的债券进入发行规模加权的样本汇总。跨市场重复身份只计一次，非空冲突会明确显示并暂停该券参与汇总。部分样本不发布为全国完整结果，原有快照与更新记录保持独立。

在 2026-09-11，当前本机保存了 101 只债券，其中 100 只有部分资料，1 只「26河北23（809336.IB）」可参与样本计算。该券位于「2025-08-08 当天及以后发行」组。每券的「查看来源」可以核对字段证据；导出遵循当前日期、发行组、地区、类型和搜索条件。

## 启动

需要 Node.js 20.19+（或 22.12+）与 Python 3.11+。在本目录运行：

```powershell
.\start.ps1
```

脚本检查依赖、构建前端并启动本机服务。打开 **http://127.0.0.1:8765**。按 Ctrl+C 停止网页服务，已保存的历史不丢失。

已安装依赖并构建后，也可以直接启动：

```powershell
.venv\Scripts\python.exe -m uvicorn backend.api:app --host 127.0.0.1 --port 8765
```

开发时，保持后端运行，另开一个终端执行 `npm.cmd run dev`，访问 http://127.0.0.1:5173。Vite 将 `/api` 代理到本机后端。

## 已实现

- **数据源切换**：首次默认 AKShare、选择持久化、按所选来源读取与创建任务；提交后的任务来源固定。AKShare 采集仅保存带来源说明的部分样本，不隐式调用 Wind，不覆盖 Wind 完整快照。
- **AKShare 全市场同步**：独立持久化任务、公开目录与逐券静态资料、目录分页完整性检查、进度查询、暂停与断点继续。目录总量只有实际获取后才确定，静态同步完成与逐券行情覆盖分别标记。
- **估值工作台**：37 个地区、两个发行日期组、七个期限、三个债券口径；日期日历、筛选搜索、表内横纵滚动、固定表头和地区列、键盘操作、详情抽屉、规则说明、CSV 导出。
- **实际计算**：对规范化个券输入进行（演示模式使用合成个券）身份去重、必需数据缺失检查、剩余期限 HALF_UP 四舍五入、发行规模加权；暂不进行条款筛选。有效零收益率保留，空组为 null，兵团独立统计。
- **历史与重试**：每个成功日期保存完整 1,554 个位置；事务原子发布，失败和无数据响应不撤销已有成功快照；任务先持久化，再由独立 Python 进程执行。刷新或关闭页面不影响已提交任务。
- **更新记录**：展示运行状态、实际生成时间、筛选数量与失败原因；支持手动更新、失败重试及待处理日期补取。SQLite 部分唯一索引避免同日重复排队，进程锁保证串行执行。
- **演示 AI 助手**：按当前视图与自然语言中的明确条件查询；历史对比展示收益率 BP、样本数和规模变化；摘要列出同口径组内变化与版本。查询不触发取数，数值、差值和排序均由固定程序计算。
- **Wind 配置**：检查 Key 格式、使用 Windows 当前用户 DPAPI 加密后存入 `runtime/wind-config.sqlite3`，支持显隐输入、撤销修改、真实握手及工具发现。浏览器不持久化 Key，接口不回显 Key；重启后自动读取。也支持后端环境变量 `WIND_KEY`。
- **多工具取数与溯源**：原始请求、响应片段、完整响应、失败原因、工具目录、名单分批证据、规范化个券、逐字段来源、筛选依据及计算结果存入 SQLite。失败与重试分别留档；页面 `/trace` 支持按任务查看、字段定位和完整 JSON 导出。新任务同时保留映射与计算代码，摘要重生成保留历史版本。
- **摘要隔离**：估值发布后生成版本绑定的模板摘要；摘要失败不回滚估值。自动摘要覆盖两个发行日期组，按发行组、期限和债券口径分别比较。

## 演示边界

### 大模型配置界面

侧栏「大模型配置」或 `/models` 支持 OpenAI 兼容 Chat Completions 服务：填写 Base URL、模型 ID、API Key 及是否鉴权，保存后可测试指定模型的真实回复。测试仅发送固定短消息，不发送行情数据；可能产生少量服务调用费用。请求使用后台固定默认超时，无需配置。

服务地址、模型与鉴权设置持久化到 SQLite；Key 仅存于后端进程内存，重启后需重填。更换服务地址需重新填写 Key。支持撤销未保存修改和清除已保存配置。测试通过后，助手仍显示规则演示模式，本次新增配置与连接验证界面，尚未启用模型参与行情解读。

显式演示模式的行情和初始运行场景均为**合成数据**。默认真实模式没有演示快照。

助手采用有限的中文规则解析与模板摘要，**未连接大模型服务**。支持明确日期、地区名称或简称、档位、发行日期组、期限和债券口径；无法确定基准日时会要求补充。比较按“第一个明确评估日作为目标、第二个作为基准”解析，并在回答中显示实际范围。相对日期需改写为明确日期。回答保留它自己的分析日期和快照版本。

“验证真实连接”仅检查官方 MCP 握手。“核验工作台数据”会执行真实工具调用，检查名单、基础资料、收益率和剩余期限的可用性，按查询日期归档。旧核验报告保留并标为历史规则结果。部分样本不代表已取得完整债券范围。

每日北京时间 09:00 的系统计划任务**未安装或启用**。可手动执行以下入口，演示处理前一自然日及缺失历史回补：

```powershell
.\scripts\daily-demo.ps1
```

后续批量取数仍需完整名单及计算必需字段。条款、额外日期和口径证明列不再构成当前取数门槛；余额仍单独记录，不替代用于加权的发行规模。原表的 4202 曲线等未返回输入暂不补造。尚未安装定时任务，尚未接入大模型意图解析。

主要接口：`GET /api/bootstrap`、`GET /api/calendar`、`GET /api/datasets/{date}`、`GET /api/rules`、`GET /api/runs`、`POST /api/runs`、`POST /api/analysis`、`GET /api/summaries/{date}`、`GET/POST /api/source`、`POST /api/source/provider`、`POST /api/source/test`、`POST /api/source/discover`、`POST /api/source/verify`。API 文档：http://127.0.0.1:8765/docs。

`POST /api/source/provider` 接受 `{"provider":"akshare"}` 或 `{"provider":"wind"}`。`GET /api/source` 保留 Wind 配置状态，同时返回 `activeProvider`、可选数据源及 AKShare 状态。`POST /api/runs` 可选传入 `provider`，省略时采用已选择的数据源；该参数只绑定本次任务，不更改全局选择。列表、日历、规则、已有数据、摘要和助手读取均遵循所选数据源。

全市场同步接口：`GET /api/akshare/sync?target=YYYY-MM-DD` 读取该日期最近的同步任务（没有时为 `null`），`POST /api/akshare/sync` 接受 `{"targetDate":"YYYY-MM-DD"}` 并返回 `202`。`POST /api/akshare/sync/{jobId}/pause` 暂停，`POST /api/akshare/sync/{jobId}/resume` 从相同任务继续。同步入口明确使用 AKShare，当前页面选择 Wind 也不会把同步任务转成 Wind 查询。

已有数据接口：`GET /api/datasets/{date}/available`，返回个券、字段证据、覆盖数量与非空样本汇总，不执行采集或快照发布。`GET /api/bootstrap` 的 `latestSavedDate`、`availableDates` 表示已有样本日期，`latestDate` 仍仅表示已发布完整结果的最新日期。

页面使用轻量接口：`GET /api/datasets/{date}/available/summary` 返回汇总、覆盖率及筛选计数，`GET /api/datasets/{date}/available/page` 返回当前页，支持 `page`、`page_size`（1–100，默认 25）、`cohort`、`tier`、`scope`、`region`、`status`、`q`。`GET /api/datasets/{date}/available/{code}` 按需读取单券与来源证据；完整 `/available` 接口继续用于全部筛选结果的导出。AKShare 保存时原子更新摘要和个券索引，已有旧缓存首次读取时补建索引。

同步使用三个隔离查询进程，共享 150 毫秒请求起始节流；仍保留暂停、断点恢复、错误重试及限流停止。首轮优化的本机实测同步从 105 提升到 269 只/分钟，后台同步期间列表首屏由约 4.3 秒降至 0.34 秒，见 [首轮性能验证](research/performance-20260912/results.md)。

后续批次按目录、详情、来源证据及同日行情的变化复用未变个券，只序列化和写入改变的记录。普通行情采集发布新版本、基准变化或进程重启时重新合并；汇总仍从全部样本精确重算。18,540 只券的离线对照中，250 只详情增量发布由 4.10 秒缩短到 0.38 秒，完整逐券与汇总结果相同。同步后的 `akshare_datasets.payload` 可采用 `akshare-index-v1` 元数据格式；内部读取和完整导出通过同一个 SQLite 事务重建个券集合，旧 JSON 缓存仍受支持。诊断脚本也兼容两种格式。

第二轮真实任务连续 3 分钟实测为 351 只/分钟，较调整前同长度窗口的 242 只/分钟提升约 45%。后台同步期间首屏 0.36 秒，完整导出和 249 项后端测试通过。条件与证据见 [第二轮性能验证](research/sync-performance-v2/results.md)。

溯源接口：`GET /api/trace/sessions`、`GET /api/trace/sessions/{id}/requests`、`GET /api/trace/requests/{id}`、`GET /api/trace/runs/{id}/observations`、`GET /api/trace/sessions/{id}/export`。
